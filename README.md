# 📋 아이디어 기획서 — 코치조의 ALPHA 육성 센터

## 소개

**코치조의 ALPHA 육성 센터**는 할 일(투두), 포모도로 타이머, 캘린더를 한 앱에 담은 macOS 26 전용 생산성 앱입니다.
Liquid Glass 디자인, 데스크톱 위젯, 메뉴 막대 타이머를 지원하고, 서버·로그인 없이 모든 데이터를 내 Mac에만 저장합니다.

- 목표(카테고리)별 투두, 루틴(반복 할 일), 하루 일기, 완료한 목표 색이 쌓이는 달성 캘린더
- 알림이 확실한 포모도로, 일정 관리 캘린더
- 하루 할 일을 모두 끝내면 나오는 축하 효과

```bash
scripts/install.sh   # 빌드 → /Applications 설치 → 실행 (자세한 내용은 아래 "개발 현황")
```

## 1. 기획 배경

### 1.1 문제 정의

- 투두메이트는 할 일 관리 경험이 뛰어나지만 **모바일 중심**이라 Mac에서 작업하면서 쓰기 불편하다.
- 할 일, 포모도로 타이머, 캘린더가 **각각 다른 앱**으로 흩어져 있어 화면과 흐름이 계속 끊긴다.
- 많은 생산성 앱이 **회원가입과 클라우드 동기화를 강제**해 가볍게 쓰기 어렵고, 개인 데이터가 외부 서버에 저장된다.
- macOS 26의 새 디자인 언어인 **Liquid Glass를 제대로 활용한** 생산성 앱이 아직 드물다.

### 1.2 해결 방향

- 투두리스트, 포모도로, 캘린더를 **한 앱 안에 통합**하고, 세 기능이 서로 데이터를 주고받게 한다.
- **로그인 없이 설치 즉시 사용**할 수 있고 모든 데이터는 사용자의 Mac에만 저장한다.
- **데스크톱 위젯**으로 앱을 열지 않고도 할 일 체크, 타이머 시작, 일정 확인이 가능하게 한다.
- Liquid Glass와 **사용자가 고를 수 있는 한글 서체**로 "매일 열고 싶은" 앱을 만든다.

## 3. 타깃 사용자

### 페르소나 A — 학생 개발자

- Mac으로 수업, 과제, 개인 프로젝트를 동시에 진행한다.
- 과제 마감일은 캘린더로, 공부는 포모도로로 관리하고 싶다.
- 회원가입 없이 바로 쓰는 가벼운 앱을 선호한다.

### 페르소나 B — 투두메이트 사용자

- 휴대폰으로 투두메이트를 쓰지만 Mac 작업 중에는 휴대폰을 집어 드는 게 번거롭다.
- 목표(카테고리)별 색상, 체크 시 쌓이는 캘린더 기록 같은 투두메이트 감성을 Mac에서도 원한다.

## 4. 핵심 가치

1. **통합** — 할 일, 집중 시간, 일정이 하나로 연결된다.

4. **감성** — Liquid Glass와 직접 고르는 서체로 나만의 앱을 만든다.

**알림 동작 원칙**

- 타이머 시작 시점에 `종료 시각`을 계산해 **알림을 미리 예약**한다. 앱이 멈추거나 백그라운드로 가도 정확히 울리게 하기 위함이다.
- 일시정지, 재설정 시 예약된 알림을 취소하고, 재개 시 다시 예약한다.
- 타이머 상태는 "남은 초"가 아니라 **시작 시각 + 총 길이**로 저장한다. 앱을 껐다 켜거나 위젯에서 보더라도 남은 시간이 정확하게 계산된다.
- 첫 실행 시 알림 권한을 요청하고, 거부된 경우 설정 화면에서 시스템 설정으로 바로 가는 버튼을 제공한다.

### 5.4 세부 기능 ① 위젯

각 주 기능을 macOS 데스크톱 및 알림 센터 위젯으로 제공한다. macOS 26에서는 위젯에도 Liquid Glass 스타일이 적용된다.

| 위젯 | 크기 | 표시 내용 | 위젯에서 가능한 조작 |
| --- | --- | --- | --- |
| 오늘의 할 일 | 소 / 중 / 대 | 소: 완료율 링 / 중·대: 목표별 할 일 목록 | ✅ 체크박스로 바로 완료 처리 |
| 포모도로 | 소 / 중 | 남은 시간(실시간 카운트다운), 현재 세션 종류, 오늘 완료 횟수 | ▶️ 시작 / ⏸ 일시정지 / ⏭ 건너뛰기 |
| 캘린더 | 소 / 중 / 대 | 소: 오늘 날짜 + 다음 일정 / 중: 이번 주 / 대: 월간 + 완료율 | 날짜 클릭 시 앱에서 해당 날짜 열기 |

- 위젯 안의 버튼은 **App Intents 기반 인터랙티브 위젯**으로 구현한다.
- 타이머 카운트다운은 위젯을 매초 갱신하지 않고 `Text(timerInterval:)`을 사용해 시스템이 그리게 한다.
- 위젯 설정에서 표시할 목표, 서체 등을 고를 수 있게 한다 (P1).

### 5.5 세부 기능 ② 서체 선택

설정에서 앱 전체 서체를 고르고, 위젯에도 같은 서체가 적용된다.

| 서체 | 성격 | 추천 용도 |
| --- | --- | --- |
| 시스템 기본 (SF Pro / Apple SD 산돌고딕 Neo) | 기본값, 가장 안정적 | 기본 |
| Pretendard | 깔끔한 고딕, 가독성 최상 | 정보량 많은 화면 |
| G마켓 산스 | 굵고 단단한 고딕 | 제목, 숫자 |
| CookieRun | 둥글고 귀여운 느낌 | 캐주얼 테마 |
| 페이퍼로지 | 부드러운 현대 고딕 | 전체 본문 |
| 카페24 써라운드 에어 | 가볍고 둥근 손글씨 느낌 | 감성 테마 |
| Anthropic Serif | 세리프, 차분한 인상 | 회고, 일기 |

- 서체 파일을 **앱 번들과 위젯 확장 둘 다에 포함**해야 한다. DMG로 받은 사용자의 Mac에는 이 서체들이 설치되어 있지 않기 때문이다.
- 서체 선택 화면에서 각 서체로 된 **미리보기 문장**을 보여준다.
- 서체마다 굵기 종류가 다르므로, 앱 내부에서는 Regular / Medium / Bold 세 단계로 매핑해 사용한다.
- 고급 옵션(P2): 제목 서체와 본문 서체를 따로 지정.

> ⚠️ **서체 라이선스 확인 필수** — DMG로 배포하면 서체 파일을 앱에 담아 재배포하게 된다. 각 서체의 "앱 임베딩 / 재배포" 허용 여부를 배포 전에 확인해야 한다.
> - Pretendard, 페이퍼로지: SIL OFL 계열로 알려져 있어 앱 포함이 비교적 자유로운 편
> - G마켓 산스, CookieRun, 카페24 써라운드 에어: 무료 상업용 서체지만 각 배포처 라이선스 문구에서 "임베딩" 조항 확인 필요
> - **Anthropic Serif**: 일반 공개 배포 서체가 아닐 가능성이 높음 → 개인용 빌드에만 넣고 공개 배포판에서는 제외 권장

## 7. 디자인 가이드

> 투두메이트에서 추출한 컬러·타이포·컴포넌트 규칙은 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)에 정리되어 있다. 아래 원칙과 충돌하면 DESIGN_SYSTEM.md가 우선한다.

### 7.1 Liquid Glass 적용 원칙

- **콘텐츠는 선명하게, 도구는 유리로.** 할 일 목록, 캘린더 칸 같은 콘텐츠 영역은 불투명하게 유지하고, 사이드바·툴바·플로팅 버튼·타이머 컨트롤 같은 **조작 레이어에 Glass를 적용**한다.
- 사용할 주요 SwiftUI API

| API | 적용 위치 |
| --- | --- |
| `.glassEffect()` | 사이드바 타이머 배지, 플로팅 버튼 (목표 칩은 투두메이트식 회색 캡슐로 변경) |
| `GlassEffectContainer` | 여러 Glass 버튼이 모여 있는 타이머 컨트롤 영역 (합쳐지고 분리되는 모핑 효과) |
| `.glassEffectID(_:in:)` | 타이머 시작 ↔ 일시정지 버튼 전환 애니메이션 |
| `.buttonStyle(.glass)` / `.glassProminent` | 일반 버튼 / 주요 버튼 |
| `NavigationSplitView` | 사이드바 (macOS 26에서 자동으로 Glass 적용) |

- 목표 색상은 콘텐츠(칩 이름, 체크박스 채움, 일정 막대)에만 단색으로 쓰고, Glass 컨트롤의 주요 버튼은 검정(`DS.ink`) tint를 쓴다.
- 투명도 줄이기(손쉬운 사용) 설정을 켠 사용자를 위해 대비가 무너지지 않는지 확인한다.

### 7.2 컬러

- 목표 / 일정 색상 팔레트: 10색 내외 프리셋 + 사용자 지정
- 완료 상태: 목표 색상으로 채운 둥근 사각형 + 흰 체크, 미완료: 회색(`#D5D9DC`) 채움

### 7.3 모션

- 체크 시 짧은 스프링 애니메이션 + 햅틱 대신 가벼운 사운드 (옵션)
- 타이머 종료 시 링이 Glass 모핑으로 다음 세션 색으로 전환

## 8. 기술 설계

### 8.1 기술 스택

| 영역 | 기술 |
| --- | --- |
| UI | SwiftUI (macOS 26 SDK), Liquid Glass API |
| 데이터 | SwiftData (로컬 SQLite 기반) |
| 위젯 | WidgetKit + App Intents (인터랙티브 위젯) |

| 설정값 | `@AppStorage` (App Group `UserDefaults`) |
| 개발 도구 | Xcode 26, Swift 6 |

### 8.2 구조

```
AlphaCenter.app
├── 메인 앱 타깃 (SwiftUI)
├── 위젯 확장 타깃 (WidgetKit)
└── 공유 모듈 (Shared)
     ├── 데이터 모델 (SwiftData @Model)
     ├── App Intents (할 일 완료, 타이머 제어)
     ├── TimerEngine (시작 시각 기반 계산)
     └── FontManager (서체 등록 / 매핑)

데이터 저장 위치: App Group 공유 컨테이너
→ 앱과 위젯이 같은 SwiftData 저장소를 읽고 쓴다.
→ 데이터 변경 시 WidgetCenter.reloadTimelines() 호출
```

### 8.3 데이터 모델 (초안)

| 모델 | 주요 필드 |
| --- | --- |
| Goal (목표) | id, 이름, 색상, 아이콘, 정렬 순서, 보관 여부 |
| Todo (할 일) | id, 제목, 날짜, 완료 여부, 완료 시각, 메모, 정렬 순서, 목표(관계), 반복 규칙, 알림 시각, 포모도로 횟수 |
| RepeatRule (반복) | 주기(일/주/월), 요일, 종료일 |
| Event (일정) | id, 제목, 시작, 종료, 종일 여부, 색상, 메모, 반복 규칙, 알림 |
| PomodoroSession | id, 종류(집중/짧은 휴식/긴 휴식), 시작 시각, 길이, 완료 여부, 연결된 할 일 |
| TimerState | 현재 종류, 시작 시각, 총 길이, 일시정지 시 남은 시간, 사이클 회차 |
| DailyNote (P2) | 날짜, 한 줄 회고, 기분 |

### 8.4 핵심 기술 포인트

- **타이머 정확도**: 남은 시간 = 총 길이 − (현재 시각 − 시작 시각). 매초 저장하지 않는다.
- **위젯 ↔ 앱 동기화**: 위젯에서 체크하거나 타이머를 시작하면 App Intent가 공유 저장소를 수정하고 알림도 다시 예약한다.
- **서체 등록**: 앱과 위젯 확장 각각의 번들에 서체를 넣고 `CTFontManagerRegisterFontsForURL`로 등록한다. 선택한 서체 이름은 App Group `UserDefaults`에 저장해 위젯도 같은 값을 읽는다.
- **반복 할 일**: 미리 수백 개를 만들어 두지 않고, 해당 날짜를 열 때 반복 규칙으로 인스턴스를 생성한다.

## 9. 배포 계획 (DMG)

| 단계 | 내용 |
| --- | --- |
| 1. 빌드 | Xcode → Product → Archive |
| 2. 서명 | Developer ID Application 인증서로 서명 |
| 3. 공증 | `notarytool`로 Apple 공증 → `stapler`로 티켓 첨부 |
| 4. 패키징 | `create-dmg` 등으로 "Applications로 드래그" 배경이 있는 DMG 생성 |
| 5. 배포 | GitHub Releases 등에 업로드 |

> ⚠️ **Apple Developer Program(유료) 가입 여부가 중요하다.**
> - 가입 시: Developer ID 서명 + 공증으로 다른 사람 Mac에서도 경고 없이 실행된다.
> - 미가입 시: 다른 사람 Mac에서 "확인되지 않은 개발자" 경고가 뜨며 시스템 설정에서 직접 허용해야 한다. 또한 **위젯 확장과 App Group은 정식 서명이 없으면 제대로 동작하지 않을 수 있다.** 개발 초기에 꼭 테스트해야 하는 항목이다.
> - App Store 밖 배포에서는 App Group ID를 `팀ID.그룹이름` 형식으로 지정한다.

**업데이트 방식**: P1은 앱 내 "새 버전 확인"(GitHub Releases 링크), P2는 Sparkle 프레임워크로 자동 업데이트 검토.

## 14. 개발 현황 (v1.0 구현)

> 이 폴더의 코드는 위 기획서를 바탕으로 만든 macOS 앱입니다. 앱 이름은 **코치조의 ALPHA 육성 센터** (실행 파일 `AlphaCenter`).

### 빌드 / 실행

필요: Xcode 26 이상 (라이선스 동의 완료), [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`)

```bash
scripts/install.sh            # 빌드 → /Applications 설치 → 위젯 등록 → 실행
scripts/build_app.sh          # build/코치조의 ALPHA 육성 센터.app 만 생성
scripts/make_dmg.sh           # build/AlphaCenter.dmg 생성
```

- `project.yml`이 프로젝트 원본이고, `AlphaCenter.xcodeproj`는 `xcodegen generate`로 다시 만들 수 있습니다. Xcode에서 열어 개발해도 됩니다.
- 타깃: `AlphaCenter`(앱) + `AlphaWidgets`(위젯 확장, 앱에 포함). 두 타깃이 `Sources/Shared`를 함께 컴파일합니다.
- Developer ID 인증서가 있으면 `SIGN_IDENTITY="Developer ID Application: ..." scripts/build_app.sh`로 서명합니다. 없으면 ad-hoc 서명(내 Mac 전용)입니다.

### 기획서와 다른 점 / 남은 작업

- **저장소**: SwiftData 대신 `@Observable` + 로컬 JSON 파일로 구현했습니다 (`~/Library/Application Support/AlphaCenter/`의 `data.json`, `timer.json`, `settings.json`). 백업 파일과 같은 형식입니다.
- **App Group 대신 경로 예외**: 유료 개발자 계정이 없으면 App Group을 쓸 수 없어서, 샌드박스인 위젯에 앱 데이터 폴더만 읽고 쓰는 `temporary-exception` 권한을 줬습니다. 위젯에서 바꾼 내용은 분산 알림으로 앱에 전달되고, 앱이 바꾼 내용은 `WidgetCenter.reloadAllTimelines()`로 위젯에 반영됩니다. App Store 배포나 개발자 계정 가입 시에는 App Group(`팀ID.그룹이름`)으로 바꾸는 것을 권장합니다.
- **서체 파일 미포함**: 라이선스 확인 전이라 서체를 번들에 넣지 않았습니다. `Resources/Fonts/`(앱·위젯 번들에 포함) 또는 앱 설정의 "서체 폴더 열기"에 .ttf/.otf를 넣으면 앱과 위젯 모두 자동 인식합니다.
- 위젯 설정(표시할 목표 고르기), Spotlight/단축어 App Intents, Apple 캘린더(EventKit) 불러오기, 제목/본문 서체 분리, Sparkle 업데이트는 이후 작업입니다.

